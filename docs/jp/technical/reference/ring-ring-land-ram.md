# リング・りんぐ・ランドのRAM

[日本語ドキュメント](../../README.md) | [English](../../../en/technical/reference/ring-ring-land-ram.md) | [CARDAオーバーレイ](../architecture/carda.md) | [セーブファイルの形式](save-file.md)

リング・りんぐ・ランドは、『聖剣伝説 LEGEND OF MANA』がペットを送り出すポケットステーションのゲームです。
移植ではこれをドリームキャストのVMU向けに書き直しています。
このページは、このゲームが使うRAMの全バイトを、2つの置き場所で示す地図です。
1つは元のゲームが使うポケットステーションのワークRAM、もう1つはVMU向けに書き直した版が使う1 KBの `vmu_ram` です。

元になるのは `pocketstation/src/game/ram_map.txt` です。
下の表は `pocketstation/tools/gen_ram.py doc` でそこから生成していて、テストが両者を一致させています。

## 表の見方

- **VMU** は `vmu_ram` の中のオフセットです。
  `pocketstation/tools/pack_ram.py` が、7つのテストスクリプトが各バイトに触れる回数から決めました。
  VMUのCPUで直接アドレス指定できる最初のバンクの恩恵を受けるのは配列でない項目だけなので、それを使用頻度の高い順に先に置き、次に配列、最後に小さなスタックの予備を置きます。
  `-` はVMUでは使わない項目です。
- **ポケットステーション** は元のアドレスで、ワークRAMの `0x200` 以降です。
  どのスクリプトも読まないバイトは載せていません。
- **型** は元のゲームの型です。VMUで変わるものは、VMUでの型も書いています。
- **意味** は元のゲームでの説明です。
  `0200234C` のような8桁の16進数は、その項目を使うポケットステーションの関数です。

元のゲームがまとめて読むため、並びを変えられない項目があります。
`idle_lo` と `repeat_up` は1つの16ビットカウンター、`mode_wait` と `wait_hi` ももう1つのカウンターです。
`scratch_wait` から始まる4バイトと `scratch_lo`/`scratch_hi` はハーフワードとして読まれます。
3本のリールの帯は `strip_a` から番号で引かれ、`points` から `save_tail` までの128バイトの状態ブロックはそのままカードに保存されます。
リールの窓は `fb` の最後の行を越えて `blit_a` と `blit_b` まで描きます。
VMUでのオフセットもこの並びを保っています。

VMUで形が変わる項目が3つあります。
`irq_handler` と `fiq_driver` の割り込みスロットは、コードのアドレスの代わりに小さなハンドラーIDを持ちます。
`snd_start` はカードのアドレスの代わりに、ゲームのファイル内のオフセットを持ちます。
カーネルへの2つのポインター、`kernel_calls` と `com_flags` には、VMUでの対応がありません。
